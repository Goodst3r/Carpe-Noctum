# Tools and verification scope — 1.8 Alpha

The available tool catalog and installed skill catalog were reviewed before source changes. The inspectable capability inventory is `plugin-inventory.json`. Tool availability in this conversation is the boundary of that inventory; it is not an account-wide permissions or installation audit. No plugin permissions or subscriptions were changed.

Tools actually used:

- Cloud Environment: read the active runtime readiness and enforced network policy; used local execution and installed Chromium/Playwright for rendered tests.
- GitHub: searched repository names and relevant code. Similar public names did not establish an authorized NightSweep upstream. The supplied ZIP remains this iteration's baseline; no new upstream repository or publication was created.
- Context7: resolved and queried Playwright documentation for service-worker offline testing; reliability audit retrieved the safe-integer documentation used to check import-ID behavior. Exact responses are retained beside this file.
- Wolfram: evaluated ten original synthetic RF, temperature, resistance, TDR and power reference calculations. `math-wolfram.json` and `MATH_AUDIT.md` record those assumptions and application comparisons. The subsequent GS7K/GainMaker GaN correction adds independent cable, port, drop, TDR and baseline/trial power results in `complete-workflow-wolfram.json`, compared with the current application in `complete-workflow-application.json`.
- Firecrawl: extracted the official Android local-WebView documentation. It supports the established HTTPS local origin and explicitly disabled universal/file access. The retained source and extraction are in `android-official-reference.json`; no new equipment specification was inferred.
- Figma: training audit read the existing mobile reference file and control structure. This informed consistency with existing controls; it was not an executed application test or a new design file. Screenshot download returned HTTP 403, so no downloaded Figma render is claimed.
- Data quality and Superpowers skills: guided the catalog audit, focused planning, reproduction, regression tests and independent review. The calculation, browser and code checks were executed locally; reading a skill is not a test run.

Other available services and workflow bundles were assessed for relevance. Messaging, investing, tax, sports, weather and account-management integrations have no required role in this offline application audit. Notion, Pages and Sites were not made competing project records. No source, field data or release package was emailed, published or sent to a model service. Synthetic numerical queries and public documentation were the external inputs.

Verification categories stay separate. jsdom/fake-indexeddb checks establish simulated DOM/storage behavior; Chromium establishes rendered browser behavior and service-worker offline reopening under emulation; mocked SDK tests establish build-script orchestration and artifact isolation. None proves physical Android/iPhone, Safari, Android WebView, native picker/print behavior or actual equipment operation.

The private signing key is absent from the handoff. Android source is prepared as 1.8 Alpha / code 23, but no signed 1.8 APK, actual SDK compilation, emulator run, phone update or physical storage-retention test is claimed. Historical Build 22 remains historical. Exact installed modules, firmware, measurement planes, local acceptance criteria and the already documented equipment-manual gaps remain field confirmation items.

Current test counts and final hashes belong in the generated QA and release receipts, not copied from the previous release. The isolated original 1.7 baseline report is retained separately as `baseline-1.7-results.json` (846 checks, 41 suites).
