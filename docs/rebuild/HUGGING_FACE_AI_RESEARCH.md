# Hugging Face model candidates for offline plan reading

Research date: 2026-11-15. This is a public-repository review only: no model weights were downloaded or run on project documents. The connected Hugging Face `model_search` and `space_search` calls returned `UNAVAILABLE`; the findings below use Hugging Face Hub public metadata, repository cards, README files, and file sizes, plus a Firecrawl review of the public cards. No model has been added to the app.

## Shortlist

| Priority | Candidate | What it could help with | Footprint and license evidence | Runtime evidence and limits |
|---|---|---|---|---|
| 1 — field trial | [PP-OCRv6 Tiny ONNX files](https://huggingface.co/snowfluke/ppu-paddle-ocr-models) | OCR text in a captured plan after local text detection. The mirrored detector is 1.78 MB and recognizer 4.45 MB, plus its `ppocrv6_tiny_dict.txt`. | The repository card says Apache-2.0. File sizes are from the HF Hub tree. The mirror README says its ONNX files come from PaddleOCR. | A promising small OCR experiment for ONNX Runtime Web or Android ONNX Runtime. The card gives no independent accuracy result for electrical-plan labels. The full detection/crop/recognition pipeline still needs to be integrated and evaluated against the real diagram labels; a recognizer alone does not find text. |
| 2 — test table parsing | [Table Transformer v1.1 structure recognition, ONNX conversion](https://huggingface.co/Xenova/table-transformer-structure-recognition-v1.1-all) | Recover rows, columns, and cell structure after a table region has been found, then feed cell crops to OCR. | 30.2 MB for `onnx/model_quantized.onnx` (or 33.1 MB for `model_q4f16.onnx`); upstream [Microsoft card](https://huggingface.co/microsoft/table-transformer-structure-recognition-v1.1-all) says MIT and training on PubTables-1M / FinTabNet. | `transformers.js` and ONNX files are present, making it the clearest browser-oriented table candidate found. It is a general document-table model, not a wiring diagram parser; layout and OCR results on the app's plan pages are unverified. |
| 3 — camera cleanup | [PaddleOCR correction models in the ONNX bundle](https://huggingface.co/snowfluke/ppu-paddle-ocr-models/tree/main/correction) | Correct a photographed page before OCR: UVDoc dewarping (31.6 MB), document orientation (6.7 MB), or text-line orientation (1.0–6.7 MB). | The bundle card says Apache-2.0. Sizes are Hub file sizes. | Plausible add-ons for camera captures with perspective, curl, or rotation. They add model/runtime complexity and are unlikely to help when the input is already the original vector PDF or a flat scan. No app-specific output has been checked. |
| 4 — page regions, if needed | [PP-DocLayoutV3](https://huggingface.co/PaddlePaddle/PP-DocLayoutV3) | Detect document regions and layout/reading order before table or text extraction. | Official card says Apache-2.0 and describes a PaddleOCR layout detector. The ONNX mirror file is 129.9 MB at [the bundle path](https://huggingface.co/snowfluke/ppu-paddle-ocr-models/blob/main/layout/PP-DocLayoutV3.onnx). | Useful only if page-region routing proves to be a bottleneck. At this size it is not my first on-device pick; generic page layout classes do not identify electrical connections or circuit symbols. |
| 5 — domain-adjacent experiment | [Block diagram symbol detector](https://huggingface.co/shreyanshu09/block_diagram_symbol_detection) | Propose boxes for flowchart-like shapes and arrows; it is the closest HF-trained diagram-object model found. | Model files include YOLOv5s at 14.8 MB and YOLOv5m at 42.8 MB. The repository includes a GPL-3.0 license file; confirm obligations for the specific weights and intended distribution before reuse. | Card says six classes (arrow, terminator, process, decision, data, text), trained on CBD and handwritten FC_A/FC_B block-diagram data. This is not an electrical-schematic detector: it does not establish component IDs, wire topology, or cable size, and has no demonstrated fit for this app. Treat as a data/domain lead, not a drop-in model. |
| 6 — optional large VLM study | [Florence-2-base-ft ONNX](https://huggingface.co/onnx-community/Florence-2-base-ft) | Try image captioning or region proposals as an exploratory second opinion on a diagram crop. | MIT card. The repository offers quantized ONNX components, but even its smaller variants span multiple encoder, decoder, embedding, and vision files; plan for hundreds of MB in aggregate, depending on the selected variants. | Transformers.js usage and a web demo are documented. No electrical drawing accuracy evidence was found. It is not a practical default for an offline Android WebView and generated text/boxes must be treated as fallible suggestions. |

## Additional OCR alternative

[PP-OCRv6 Small LiteRT](https://huggingface.co/litert-community/PP-OCRv6-Small-LiteRT) has a 12.38 MB detector plus a 21.48 MB recognizer (about 33.9 MB together at 320 input width), Apache-2.0 card, Android Kotlin integration examples, and a separate 21.52 MB WebGPU-compatible recognizer file. Its author reports tensor/image parity on one Samsung Galaxy S26 Android 16 with LiteRT 2.2.0 and explicit GPU FP32; the README explicitly limits that evidence to that device and synthetic fixtures. The evaluation also says source task quality is below its declared acceptance gate. WebGPU conversion parity was reported on an Apple M4 Max, not Android. This is credible integration evidence, but not proof it will read the tiny A/E labels better than current OCR. Keep it behind the Tiny ONNX trial unless the target devices and LiteRT runtime are fixed.

[TrOCR small printed in ONNX](https://huggingface.co/Xenova/trocr-small-printed) is another recognizer-only option. Its repo has quantized encoder/decoder weights of 23.1 MB + 40.2 MB and Transformers.js support; upstream describes it as fine-tuned on SROIE document text. The HF card does not declare a license, so resolve licensing before reuse. It needs well-cropped text lines and does not perform text detection; that makes it less attractive than testing the compact PP-OCRv6 detection-plus-recognition pair first.

## Recommendation for this app

Run a small, local comparison on representative synthetic crops and authorized walkout pages before selecting weights: first PP-OCRv6 Tiny ONNX for line detection/recognition, then Table Transformer only on table-heavy pages. Consider orientation/dewarp only for camera captures. Defer Florence-2 and PP-DocLayoutV3 unless a measured need justifies their larger download and runtime cost. The block-diagram model is a possible source of training ideas, not a ready electrical-symbol solution.

For any model output, show proposed text/boxes or connections for user review. Keep RF calculations, unit conversions, cable-size logic, and final takeoffs deterministic and traceable; AI recognition must not silently become an engineering decision.

## Verification notes

- Inspected Hugging Face model cards / README and public Hub file metadata for the linked repositories. Sizes above are the listed file byte counts expressed as decimal MB; grouped sizes are model weights only and exclude vocabularies, runtime libraries, and app packaging unless stated.
- A repo's license label is evidence about that repository, not legal advice about dependencies or model provenance. PP-OCRv6 Tiny and orientation assets are from a third-party mirror that states its models are sourced from PaddleOCR; confirm upstream terms at adoption.
- Hub search returned no electrical schematic detector with demonstrated weights/results. The block-diagram repo is the nearest surfaced candidate, but the domain mismatch is substantial.
- No weights were downloaded, no private map/PDF was uploaded, and no app, package, or build file was changed as part of this research.
