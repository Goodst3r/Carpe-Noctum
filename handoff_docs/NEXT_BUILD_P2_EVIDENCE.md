## Behavior and compatibility

- `company-targets.js` supplies one pure `targetAt(profileId, frequencyMHz)` evaluator, shared metadata and two explicit node-output company references: `company-42-20261113` is 32 @ 54 / 43 @ 753 MHz; `company-aoi-v15` is 34 @ 261 / 49 @ 1215 MHz. Both use linear MHz interpolation only inside their inclusive domains. Blank, nonfinite and out-of-domain frequencies return an unavailable value with a reason. Lookup returns units, domain, source and missing-basis metadata; display uses 0.1 dB while numeric checks use 1e-9 dB.
- Plan → Setup has an explicit reference selector and Apply action. Apply requires a node with the matching installed split and hardware covering the reference domain. It changes the launch design anchors/levels and view/reference frequencies, selects linear interpolation, disables extrapolation and remaining test-point addback, and preserves Station measurements, amplifier targets, hardware and available-spectrum limits. Selecting Legacy keeps the entered launch values. No preset is applied on opening an old job.
- The optional `setup.companyTargetProfile` scalar uses the existing schema-one setup extension; no new store, storage key, version, package or migration is introduced. Invalid selector metadata is rejected atomically. Both saved legacy pairs, 31 @ 54 / 43 @ 860 and 34 @ 261 / 46 @ 993, retain their saved inputs and calculations. Unknown ancillary data, partial Station readings and original evidence bytes survive named duplication, actual job switching and portable export/import.
- Company targets are a separate reference, not automatic Station or amplifier targets. Station shows independent manual worksheet results and a separately labelled company node reference. Valid manual per-pilot errors can display without the other reading or a complete solver; invalid order and installed-band guards still apply. Choosing a Plan reference does not suppress existing independent node/amp worksheet results. The Station render signature includes the reference so that the separate panel refreshes on selection/removal.
- Company absolute errors, target-relative tilt error and acceptance remain unavailable while bandwidth, power convention, impedance, measurement-plane agreement and field tolerance are unconfirmed. The source does not invent a confirmation path. One target may display while another is unavailable. Derived raw tilt overflow becomes unavailable.
- Field meter readings and predictions remain visible. Meter-minus-prediction is held when that prediction derives from the selected company launch design; independently entered profile targets, tolerances and inside/outside comparisons remain separate and unchanged.
- Existing Project records/criteria and grading criteria are not automatically adopted into the new company reference. Project rendering and CSV preserve independent approved records. An explicitly associated scalar `companyTargetProfile` on a Project record/profile holds its dependent company comparisons; the already-flexible scalar record/profile format is unchanged, and no new association UI is introduced. The sweep evaluator accepts an explicit company context for dependent callers, preserving raw peak-to-valley/tilt while holding absolute checks. The grading UI does not apply the Plan reference to independent criteria or invalidate their history merely for that choice. No grading-association field or adoption action was invented.
- Tools → References and Limits, Meter setup and Project reference/export notes expose the shared provenance. Four Company registry rows are included in the existing Limits grouping. Technician/Functions guides explain explicit application, retained legacy behavior and the unknowns.
